# Transition Lab: public synthetic visual benchmark

This website visualizes generated source motions through the current reviewed
runtime on `main`. It publishes only synthetic, allowlisted demo media. This is
not a harness release or publication of private source assets.

## What is shown

`tools/sequence_fixture.py` creates, exports, indexes, transfers and sequences the
actual generated source motions through the reviewed runtime. That entire fixture
must pass before `tools/transition_showcase.py` reads its authoritative result.

Four methods are sampled from actual Blender-evaluated Actions/NLA at 30 FPS:

1. Unaligned hard cut.
2. Native NLA REPLACE crossfade, no spatial alignment.
3. Aligned NLA control: same explicit yaw, incoming anchor matched to outgoing
   anchor at the START of the overlap, then normal crossfade.
4. The actual Director result: complete A, additional endpoint bridge, complete B.

A crossfade overlaps source time; Director adds time. Their B source phases and
full sequence lengths therefore differ. This is disclosed, not concealed by
resampling or forcing all panels to show the same B pose. No method is claimed to
be universally better. The stronger aligned-NLA control may also look good.

One constant stage-coordinate transformation, identical simple joint geometry,
lighting, and a locked camera are used in all views. The display geometry is NOT
the fixture skin and NOT a production mannequin. It follows observed joint heads.
The green floor trace is the projected hips, not a contact-state classifier.

The clip is a four-second viewing excerpt: 120 frames per method, 480 renders
maximum, 480x360 each, 8-sample Cycles CPU, two threads. The encoded 960x720 H.264
comparison has 120 frames at 30 FPS, duration four seconds. Last sampled pose is
at 119/30 seconds, displayed for one frame. The full ~37-second B exists in the
validated sequence, but is NOT entirely rendered in this small public demo.

Synthetic motion is a simple glide/arm gesture, not a moonwalk, Thriller capture,
realistic dance, or proof of naturalness. No private Mixamo assets are used.
The fixture's synthetic grant/revocation tests do not represent real Adobe license
review. No grants or raw library reports are published with the visualisation.

## Build and deployment

`.github/workflows/transition-lab-pages.yml` validates pull requests, main and the
one-time consolidation branch. Only the main push/manual path can deploy; PR
builds cannot publish. Each build creates its own media from the same source SHA,
rather than relying on an expiring artifact from a different revision.

The build runs offline/unit/packaging gates, the actual long-sequence fixture,
bounded renders, FFmpeg media validation and Playwright desktop/mobile checks.
Only the allowlisted HTML/CSS/JS, metrics JSON, JPEG poster, MP4 and `.nojekyll`
enter the Pages artifact. No .blend/FBX, configurations, library databases or
private reports are copied. Browser screenshots remain a diagnostic artifact.

The separate deploy job has `pages:write` and `id-token:write`, reads existing
Pages settings, and uses official GitHub Pages actions. It does not automatically
enable Pages or relax environment/branch protections. If repository settings
prevent deployment, retain the built preview and report the actual blocker.
All automated tests and renders run in GitHub Actions, not a user's workstation.

Manual controls: native player scrub/fullscreen, 0.25x/0.5x/1x playback, restart,
and jump to the first transition interval. Metrics/trajectory are generated by
the Blender capture, never hand-entered as demo outcomes. A video or a passing
browser test does not establish artistic acceptance.
